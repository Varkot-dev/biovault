What you just did

This is the differencing attack. Ask for a count, ask again with your target excluded, subtract. Against exact counts it discloses that person's genotype precisely — no bug required, the API working as designed is enough.

Laplace noise blunts a single attempt. But noise is zero-mean: repeat the query and average, and it cancels. That is why the enforced budget — not the noise — is the actual control. A differential-privacy implementation with correct noise and unenforced accounting provides no guarantee at all, only the appearance of one.

Why ε = 1.0 and not 10.0

The default was chosen by measuring this attack rather than copying a convention. A federated query costs ε × the number of sites, so across three labs a budget of 1.0 at ε = 0.1 buys three queries. Measured over 400 full attacks each, recovering a true count of 500:

Where this still fails

Even at the BioVault default, 14.5% of measured trials still landed within ±1 of the true count. Differential privacy bounds expected leakage; it does not eliminate it. Spam the attack a few times at ε = 1.0 and you will win some of them. That number is published rather than hidden because a privacy claim you cannot falsify is not a claim.

Noise here is Laplace(0, 1/ε) drawn from crypto.getRandomValues, matching secrets in the Python implementation — a predictable PRNG would let an attacker subtract the noise while every statistical test still passed.
